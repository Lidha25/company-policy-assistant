Rules-based search is fast and uses no AI tokens because it returns matching policy text, but keyword matching can select an irrelevant policy or miss a question phrased differently. The LLM without a vector index receives all 98 policy entries for each question, which provides broad context but uses more tokens and can still add unsupported details. The LLM with a vector index uses Gemini Embedding to retrieve five semantically related entries before generation, reducing the policy text sent to Gemini while risking that a relevant condition is left out. In the saved 12-question sample, the AI-assisted review flagged unsupported factual claims in 0/12 answers for each method; it separately found 3/12 rules answers incomplete or irrelevant, 0/12 full-context answers, and 1/12 vector answers incomplete. For this 98-entry database, the full-policy approach is the preferred fit because the model can see every policy record instead of depending on a short retrieved subset. It used more generation tokens than vector search in the saved test, while rules-based search remains a quick, no-token baseline. The vector card reports generation tokens and adds query-embedding tokens when Gemini reports them; when embedding usage is absent, it marks the complete token total unavailable instead of presenting the generation subtotal as the total. Current-question response time and token use are measured from each successful run, while the unsupported-claim rate is transparently identified as a small, AI-assisted reviewed sample awaiting student verification.
