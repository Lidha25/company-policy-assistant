Rules-based search is fast and uses no AI tokens because it returns matching policy text, but keyword matching can select an irrelevant policy or miss a question phrased differently. The LLM without a vector index receives all 98 policy entries for each question, which provides broad context but uses more tokens and can still add unsupported details. The LLM with a vector index uses Gemini Embedding to retrieve five semantically related entries before generation, reducing the policy text sent to Gemini while risking that a relevant condition is left out. For this 98-entry database, the full-policy approach is the preferred fit because the model can see every policy record instead of depending on a short retrieved subset. It may use more tokens than vector search, while rules-based search remains a quick, no-token baseline. Rules-based search has less risk of inventing wording because it quotes stored text, though its match can still be irrelevant; both LLM approaches can add unsupported details and need claim-by-claim checking. The risk descriptions are qualitative rather than a statistical rate, and response time and token use are measured for each successful question rather than copied from an old batch run.
